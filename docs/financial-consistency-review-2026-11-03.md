# 财务一致性、支出台账CSV与安全精简报告

日期：2026-11-03（日本时间）。基线：main `eae74f8c77607bf18b953bbec3dfe4bf8f3bf6bd`，提交前已再次核对远端。仅提交PR供检查，不合并、不上线。

## 1. 财务一致性优先

先运行原有基线，再新增失败测试，确认两种并发缺陷：

| 场景 | 修复前实际结果 | 修复后 |
| --- | --- | --- |
| 同一支出由CSV/手动新建入口与银行明细新建入口同时提交 | 测试得到2条费用，预期1条 | 新建费用复用原有expenseKey及CSV稳定标识，事务冲突后重试或保留待人工照合，费用仅1条 |
| 已确认规则自动生成银行手续费，同时导入相同费用CSV | 测试得到2条费用，预期1条 | 自动手续费复用原有saveExpense去重路径，仅1条费用 |

修改仅涉及新费用标识选择。保留历史expense_bank标识检查；不改已有记录ID、不迁移历史、不重写队列命令或operationId指纹。已有银行照合重放仍核验双向引用；不一致时保持冲突，不能静默清队列。

新增回归还覆盖：提交已成功但确认响应丢失，命令仍在离线队列；重建同步器后从存储恢复同一个命令，重放不增加费用、现金镜像或版本。真实浏览器中两台独立设备离线提交相同费用，一台停止旧同步器、重载页面并重新登录，从本地存储恢复队列；另一台恢复联网；最终只有1条费用及1条现金镜像。再次重放原命令仍不增加记录。

继续通过的既有覆盖包括：不同入金ID并发不能超收、正式领收书复用入金、银行CSV重复导入、照合/解除/再照合、现金与代表者立替隔离、借记卡与信用卡分开处理、前渡金不生成费用、月次材料请款仅生成一次费用/扣减、并发版本冲突、审计与权限边界。没有因为精简而删除这些保护。

## 2. 统一来源与CSV

支出台账显示、当前月CSV、HOME的费用统计与业务明细现在共用 `expenseRegister`，复用既有 `live`、稳定ID去重、期间校验及 `expenseStatus`。只按稳定ID去重，不按日期/金额合并不同ID的真实支出。排序固定为支出日期升序，同日以稳定ID排序。清空月份后回到当前月。

「支出・現金 → 支出台帳」新增「CSV出力」，保留「支出CSV取込」。CSV每笔费用一行，含：支出日、科目、取引先、内容、支払方法、金額、状態、領収書参照。支付方式与状态分列；金额为数值；不输出费用ID、银行内部ID或取消日期。使用原有CSV编码器：UTF-8 BOM、CRLF、引号转义、多行文本及公式前缀防护；已从真实下载文件验证字节和内容，未依赖Excel桌面软件验证。

| 数据用途 | 来源与口径 |
| --- | --- |
| 支出台账/费用CSV/HOME费用 | 同一费用记录、有效状态、费用日期和稳定ID选择；相同期间金额一致 |
| 売上・入金台账 | 既有salesRegister/ledger/receivables；売上日期决定业务期间，入金日期及基准日决定入金和余额 |
| HOME入金 | 仅有效且已确认的入金；银行收入与现金收入分开，前渡金不计收入/费用 |
| 未収详情与通知 | 既有Outstanding.view复用unique/live/confirmed；待确认入金可在历史中显示，但不减少已确认未収 |
| 正式帐票 | 保持原始快照、日期、编号及关联；打开/再下载不重复记账 |

台账与HOME在不同所选期间本来就可能不同；测试在相同期间比较行数、顺序和金额，不把应收余额时点与当期入金流量混为一谈。银行、现金和年度审计用的原有专用导出保留。

## 5. 风险与边界

- 修复针对已复现的相同expenseKey并发重复成本；不同日期、内容、支付方式或口座描述同一经济事项，仍需凭原本人工照合，不能自动认定相同或删除。

- 自动化验证不能证明正式历史数据无异常；没有对正式数据做审计查询，也未在真实Excel或物理手机上验收。
