## 根因与变更

1. 旧 CSV hash 包含自由输入的账户名，GMOあおぞら与メイン口座生成不同 ID；没有账户别名模型。新增审核保存的“别名→实账户固定名”规则。相同银行不同实账户仍须保持不同固定名。
2. 导入事务以固定账户名＋银行交易编号优先；无编号时使用日期、完整规范化摘要、方向金额、交易后余额、occurrence。新 ID 为该身份的 SHA-256 截取 48 位。原始账户、摘要、hash、occurrence 保留。先查已有强身份记录，再查确定性 ID，重复导入只读返回，不重写旧记录。没有编号和余额时不跨别名自动去重、不自动确认。
3. 同额交易若余额、交易编号或 occurrence 不同，仍独立保留；绝不只按日期＋金额合并。编号相同而金额、日期或摘要冲突，停止导入并报要确认。无编号且相同完整签名的重叠片段 CSV 不能单靠 occurrence 证明实体身份；需原始全量 CSV／银行凭证核对，不作历史清理。
4. 原“自動一致”只是 100 分候选，UI 仍强制点击。现在新导入证据仅在：单一完整销售／未收锚点、金额严格等于整笔业务、完整银行摘要→客户名称已审核、无多个 payment／现金／平台／已配对冲突时，在同一事务完成照合。相关记录在事务内重读，既有 sale/payment 并发控制保留。创建唯一必要 payment，不生成销售或領収書。部分、合计、名称未确认、断链、多个候选不自动记账。
5. 已确认 payment 可复用，保留 paymentDate 和原记账期间，新增 bankTxnId／bankTransactionDate；HOME 标明手工确认款项仍“銀行未照合”，已照合时另显示真实银行日。原销售日、跨月、分次收款和正式帐票不变。
6. 受取利息、普通預金利息、預金利息、利息（完整摘要匹配）识别为受取利息；振込手数料、振替手数料、銀行手数料识别为支払手数料。需一次审核启用对应会计口径，强身份无冲突才自动处理；已有同日同额支出时手续费保守留人工确认。利息只使用银行证据记录为営業外収益，不生成 sale/payment；手续费复用现有费用／照合路径。税务仍待确认，不推算预扣税或消费税。月次、年度与期间导出纳入営業外収益。
7. 全部现有科目保留，新增支払手数料。CSV 有科目优先，取引先→科目审核规则持久复用；用户手选科目不被随后输入的取引先覆盖。給与／外注費规则仍提示审核，不自动拆工资、法定扣除或凭同名推断。
8. Visaデビット／debit 不再误判为信用卡汇总结算；仍不凭商品摘要擅自创建普通费用。银行表固定日期／金额列，扩大摘要，候选与按钮允许换行，避免单行说明挤出巨大空白。手机沿用原导航结构与表内横滚。

## 旧数据与用户审核方案

**旧数据库中的重复 ID 仍然保留。代码更新不等于历史修复。**

- 用户先核对 GMOあおぞら／メイン口座是否为同一实际银行账户，确认后保存别名规则。系统不会预设所有 GMO 账户相同。
- 银行列表将强证据相同的未配对记录合为一次展示，保留原记录；同组多个已配对记录或金额／日期冲突不隐藏。余额／编号不足的记录继续分别显示，不能安全判断时保留人工审核。
- 现有“銀行照合結果CSV”新增固定账户名、交易编号、hash、occurrence、同一证据其他 ID 与审核提示；导出所有原始记录，不因页面合行省略来源。
- 对截图四组交易逐组审核：10/31 dynast 1,594,900、10/30 ネットプロテクションズ 207,949、手续费 100、10/28 Amazon Visa debit 1,172。核对银行原始 CSV、实账户、交易编号／余额链及关联 payment／expense。dynast／ダイナスト要先确认客户别名，不能以金额相等代替名称信任。
- 如需真正修复旧记录，另做逐 ID 的只读修复清单：保留 ID、拟处置 ID、证据、所有关联项、前后 KPI、预期 revision、回滚数据。用户审核后再实施单独的带审计操作。本 PR 不包含生产迁移、自动修复登录钩子、删除或批量重配对。
- 重复导入既有记录只读返回，不会借重新导入自动改变旧 payment。旧未照合项仍需审核；可信规则用于新导入证据，避免后台改历史。
