# HOME・銀行照合 最終整合修正（レビュー用）

## 変更範囲

トップの黒金ナビゲーションと月輪合同会社ブランドのマークアップ・スタイルは変更していません。HOMEは4主KPI＋2副指標、灰白の角丸カード、既定7列の月次台帳になりました。元の11列分の財務情報は各行の「詳細」に保持し、CSV・集計式は変更していません。銀行照合は行内フォームと未処理／全件／照合済の既存フィルターを使用します。

- 東鵬の前渡金：銀行行内で既存仕入先を選択、または新規仕入先名を入力できます。仕入先作成・前渡残高・銀行照合を同一トランザクションで確定。費用・追加出金・現金を作成しません。既存の月次請求と実控除処理は維持します。
- WOOC：9/28請求から10/15入金への120日候補検索をそのまま利用し、既存売上・既存入金を再利用します。断リンク帳票は具体的に表示し、銀行行内で既存売上・未収を明示選択できます。帳票の再発行や売上の自動新設はしません。
- Stripe：くらしのマーケットの既存注文入金を複数選択し、精算書参照・入金合計・既存控除手数料・銀行実入金を照合します。売上・入金・手数料の新規作成はしません。既に確定済みの入金日は保持し、未確定入金は銀行日で確定。照合解除は元の確認状態・入金日に戻します。
- 利息：受取利息として銀行行内で明示確定。営業外収益に1回だけ計上し、再試行は無変更で終了します。VISAキャッシュバックも同様です。
- その他：既存売上・未収の手動選択、銀行出金からの既存費用照合／新規費用、前渡金、原本確認後の雑収入、理由付き除外を既存の安全なコマンドで処理できます。曖昧な請求書は自動確定しません。

## プラットフォーム精算の制約

精算1件は既存入金最大5件、手数料控除ありは最大4件です。Firestoreの監査付き原子処理の上限に合わせた制約です。上限を超える精算は、同じ銀行明細を分割確定せず管理者確認が必要です。くらしのマーケットの経路・平台名が既存入金に登録されていない場合、候補がない理由を表示し、銀行明細を未照合で保持します。精算書から注文の内訳を推測しません。

## データ・権限

新しいプラットフォーム証拠更新は管理者限定です。既存入金の金額・売上ID・支払方法は変更できず、同一操作で更新される銀行明細の配賦に含まれる入金だけを照合します。既存売上の支払IDを読み取り、同時更新の競合を検出します。既存控除手数料は他の精算で再利用できず、照合中の編集・取消も拒否します。

Firestoreルールは、監査前イメージと同一操作の銀行証拠を検証する限定分岐を追加しています。既存の監査、管理者／スタッフ分離、正式帳票保護、銀行履歴の取消・復元禁止を維持しています。リリースを承認する場合は、本PRのルールをアプリ更新に先立ち別途レビュー・配備してください。本作業では配備しません。

本PRはコード修正のみです。生産Firestoreへの更新、履歴の一括変換、削除済みメイン口座31件の操作、合併、公開は実施していません。実データの各行が照合済みになったことを意味しません。
