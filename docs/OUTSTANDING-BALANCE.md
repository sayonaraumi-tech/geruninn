# 未入金残高管理

## 一つの入金データソース

正式請求書・小野田請求書の `documents` と既存 `sales` / `payments` を読み取り、`saleId` で入金を関連付けます。訂正版も元の saleId を引き継ぎます。`invoiceAmount`（正式帳票の amount）、`payments[]`（既存 payments の表示用投影）、`paidAmount`、`outstandingAmount`、`paymentStatus` は派生値です。正式 snapshot に可変の入金配列や残高を保存しません。

- paidAmount = 取消されていない入金登録額の合計。銀行照合マーカーは除外します。
- outstandingAmount = invoiceAmount - paidAmount。過入金も保持し、0 以下は入金済です。
- 0 入金は未入金、正の入金と正の残高は一部入金、残高0以下は入金済です。
- 入金日・金額・方法・備考は既存の paymentDate / amount / method / memo を使用し、表示用に date / note を投影します。

銀行振込は既存の pending-bank として登録し、残高表示には反映します。入金履歴に銀行照合待ちを表示します。記帳・月次入金・年度決算は既存の確認済み入金のみを集計するルールを維持します。銀行CSV照合は既存の入金を bank-confirmed に更新し、金額を二度追加しません。現金は既存の cash-received / cashLedger ミラーを使用します。「その他」は既存の現金以外の確認待ちルールを使用します。

## 操作と権限

保存帳票一覧・帳票保存履歴に請求額、累計入金額、未入金残高、入金状態を表示します。有効な請求書には入金登録、すべての請求書には入金履歴、有効かつ残高が正なら未入金残高請求書を表示します。

入金ダイアログは日付、整数の円、銀行振込 / 現金 / その他、備考を入力します。入金履歴には照合状態も表示します。admin / staff とも既存の audited payment トランザクションを使用し、staff の銀行確認権限は追加しません。入金と sale.paymentIds / paymentVersion、操作ID、監査を一括コミットします。二重クリック、同一操作の再試行、未同期入金がある状態での再登録を防ぎます。アカウント切替時にはダイアログを閉じます。無効帳票・異なる訂正版への入金、無効な日付・金額・方法を拒否します。

## 残高通知PDF

「未入金残高請求書」は正式帳票保存経路を呼ばない読み取り専用の出力です。元の請求額・正式snapshot・PDF・番号予約・売上・税額・収入・Calendarを変更しません。新しい documents / sales / payments は生成しません。会社のLOGO、社名、住所、電話、メール、印章、振込先を既存テンプレートから使用します。

タイトルは請求書、金額下に未入金残高のご請求を表示します。No. は元番号に（残高通知）を付け、明細にも原請求書No.を表示します。発行日は日本時間の出力日です。原請求額、入金累計、残高と差引明細、元請求の残高であり新規工事ではないことを明記した備考を表示します。数量・単価・課税区分・消費税の再計算欄はありません。

対象月は保存された billingMonth / targetMonth、元帳票の年・月記載、売上日、請求日の順で読みます。旧帳票の対象月が明確でない場合はダイアログで確認・指定できます。この指定は出力だけに使用し、原帳票を書き換えません。

ファイル名: `YYYY年M月_顧客名_未入金残高請求書_金額円.pdf`。例: `2026年7月_dynast合同会社_未入金残高請求書_9000円.pdf`。

779,379円に770,379円の入金を登録すると残高9,000円・一部入金になります。後の9,000円は既存売上に対する payment のみを追加し、残高0円・入金済になります。銀行照合が完了していれば、確認済み銀行入金770,379円と後の入金9,000円も正しく集計されます。

## 互換性とデプロイ

Firestore の新しいコレクション、保存フィールド、インデックス、Security Rules 変更はありません。migration は不要です。旧帳票に payments / 派生値がなくても既存 payments から読み、入金がなければ未入金として表示します。原帳票 amount のない互換データは既存の保存済み売上額、最後に元snapshotの既存合計計算を使います。自動の一括更新は行いません。

見積書は登録番号を表示しません。請求書・領収書・小野田請求書は2026-10-01以降の適用日条件と会社設定を使用し、右上に一度表示します。入力欄はhiddenのままです。旧正式snapshotの登録番号は保持します。

## 検証

`pnpm test`、`pnpm test:rules`、`pnpm test:browser`、`pnpm test:business-browser`、`pnpm test:document-numbering-browser`、`pnpm test:auth-persistence`、`pnpm test:outstanding-browser`。

`HTML2PDF_BUNDLE` に本番と同じ html2pdf 0.10.1 のローカルbundleを指定すると、390px / 1280pxから実際の残高PDFを出力し、非空・A4単ページを確認します。PDFは画像化して裁切れ・重なり・内容も確認します。模擬環境のdynast例を使用し、本番の顧客データ・入金は追加しません。
