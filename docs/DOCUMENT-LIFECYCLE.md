# 正式帳票の訂正・無効・重複

管理者は「保存帳票」の有効な帳票から「訂正版を作成」「無効にする」「重複として無効」を選択できます。スタッフには状態と閲覧・再ダウンロードだけを表示します。

- 訂正は理由を入力して下書きを作成します。下書きを破棄しても原本は有効です。新しい帳票を正式保存した時に、原本が訂正済、新帳票が有効になります。
- 原本の documentId、snapshot、作成日時は保持します。宛名・会社名・住所・明細・備考などの訂正は新帳票に記録します。
- 請求書・小野田請求の訂正は元の saleId を引き継ぎます。領収書の訂正は元の paymentId を引き継ぎます。見積の訂正は見積・案件の関係を保持します。
- 確認済み入金がある請求書・領収書は直接無効・重複にできません。未確認入金も先に整理してください。銀行入金は照合解除、現金入金は既存の入金取消を利用し、実際の返金は別途正しく記録してください。
- 訂正後の請求額を確認済み入金合計より小さくする操作は拒否します。確認済み領収書の金額・入金日・支払方法は領収書訂正では変更できません。
- 無効・取消・重複の売上は未収・月次・新規銀行照合から除外します。訂正済の旧帳票は参照のみで、有効な訂正版が同じ売上を引き継ぎます。
- 過去帳票に status がない場合は有効として互換読み込みします。元データを削除・一括書き換えしません。

全操作は Firestore トランザクションと監査ログに保存されます。既存入金をサーバーから確認し、新規入金は売上の paymentIds/paymentVersion と同じトランザクションで記録するため、入金と無効化の競合を検知できます。ローカルの未同期キューとバックアップは保持します。

検証: pnpm test / pnpm test:rules / pnpm test:browser / pnpm test:business-browser。ルール変更後は開いている旧バージョンのページを再読込してください。
