# PR #18 四条收付款路径的最终检查

## 变更

- 现金支出继续复用 `saveExpense` 和原子现金镜像：保存后「支払済」，现金账扣款，不进入银行候选。
- 现金施工收入复用现有日程／領収書的売上、payment、现金账关联。重复提交保持一组记录；HOME「入金済」，银行照合候选和事务入口均拒绝现金売上。
- 普通代表者立替与交通系 IC 均不扣公司现金、不进入银行候选；费用仍进入支出科目。没有精算凭证模型，不凭 memo、settled、reimbursed 或 bankTxnId 显示精算済。供应商支払入口也拒绝立替误配银行。
- 明确区分「法人銀行デビット」「法人信用カード」。旧「法人カード決済」显示卡种未设定／要确认，须人工确认类型，不猜测历史卡种。
- 信用卡识别名沿用现有 bankAccount 字段，并在支出表单显示。CSV 可选列「カード識別名」或「銀行口座」。同日同额同商户但不同卡不作重复支出合并。
- 月度信用卡引落由用户核对明细、勾选同一卡的既有费用，全额一致后原子关联。重复、不同卡、金额不符、已消费的费用和并发竞争均拒绝；解除会移除整组关联，重配对不新增费用。银行 CSV 导出保留整组费用 ID。
- 有同额近期信用卡／卡种不明费用时，禁止通过普通银行出金入口再建费用，需先审查既有记录。

## 范围和保留项

保留原 PR 的银行强证据去重、审核别名、可信唯一全额自动照合、payment 复用、利息与手续费政策、完整科目学习和原始销售日。没有修改正式帳票、Firebase 配置或 Firestore Rules；没有生产数据读取、历史迁移或批量修复。

本次月度扣款一次支持 1–5 笔费用，已按真实 Rules 验证最大组；超过 5 笔、手续费差额、跨卡／分期／退款等复杂账单保留人工审核，不允许以新增费用或部分假照合绕过。卡识别名和账单归属由用户核实，不按银行摘要猜卡号。立替实际精算的记账功能不在本次范围。
