## 草稿功能

- 银行照合页面新增管理员逐条审核区域，列出「メイン口座」和「GMO あおぞら」同日同额候选的真实 ID、版本、证据键、引用和拦截原因。候选不代表重复。
- 必须有管理员审核过的同一实际账户别名规则，以及一致交易编号或含残高、出现序号的完整强证据。摘要、方向、金额、日期冲突均拒绝；同日同额不足以取消。
- 已照合、有正向业务关联或检测到任意业务反向引用的记录一律拒绝；不解除、不重配关联。
- 提供从服务器读取所有应用业务集合与审计日志的 JSON 导出。下载含 ID、payload、版本及元数据。取消前重新读取业务记录并比较摘要，备份后修改即拒绝。
- 取消只写目标银行明细的 `status: cancelled`，嵌入原始 payload、保留 ID/版本、理由、原本核对说明、备份摘要及操作员。沿用原子审计及操作防重放。恢复写回完整原始 payload，版本继续递增，审计保留。
- 普通照合、除外和从银行创建支出不能使用已取消记录。取消后的银行明细不再列为未照合提醒，不改收入、支出、正式帳票或现金账。

## 正式启用仍受阻

**正式项目在 UI 和业务服务入口均拒绝取消、恢复。** 只有 `demo-` 测试项目允许验证草稿流程。不是正式库安全边界的替代品，不能通过去掉项目检查就上线。

原因：当前 Web SDK 只支持事务内按文档读取。先列集合、再在事务内重读已有 ID，能发现已知文档版本变化，但无法排除列集合后新建的反向引用。现有 Firestore Rules 也没有这一操作专用的服务端引用锁。本补丁不修改 Rules，不声称已解决并发新增引用的安全性。

正式启用前必须通过受信任服务端的事务查询或受 Rules 强制的引用锁，把反向引用、目标及保留记录在同一安全边界内验证，并运行真实 Rules/模拟器并发集成测试。必须保留原始银行 CSV，取得正式只读快照、完整原生 Firestore 备份及恢复验证后，逐条确定保留/取消 ID。此 JSON 是应用记录导出，不包含 operations、数据库索引或 Rules，不是原生 Firestore 恢复备份，也不是单个事务时间点快照。
