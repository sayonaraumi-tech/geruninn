# 銀行ページ内支出照合と同期キュー保護

PR #18 合併後の main を基点とした追加修正。

- 既存支出は銀行行の候補から確認。Visaデビットは旧「法人カード決済」も同額・7日以内の人工確認候補に含める。現金・代表者立替・明示的信用カードは含めない。名称差異は70点の確認候補のままにし、自動照合を緩和しない。
- 新規補録は銀行ページの専用 dialog で日付・金額・科目・取引先・内容・銀行支払方法・領収書参照・分類学習を入力。取消時は書込みゼロ。既存候補があれば新規登録を拒否し、トランザクションでも重複防止を維持する。
- ログインは既存 cloudDialog を利用し、銀行・支出入力をログイン後に復元する。管理者操作時に未ログインなら原ページで dialog を開く。
- expenseFromBank の既存支出競合は outbox 内で保持。操作ID、原コマンド、作成時刻を変更しない。初回処理前及び旧キュー読込時、`bank_conflict_backup_<operationId>` に全キューを永続化する。競合の銀行IDに依存しないコマンドは続行。同一銀行の明示的 bankMatch は通し、その他の依存コマンドは保留する。他の権限エラー・ネットワーク障害の停止動作は維持。
- 人工照合後は銀行→支出と支出→銀行の相互参照、有効状態、金額、銀行日付と原コマンド日付をトランザクション内で検証して旧補録を unchanged として完了。参照不一致は保留。既存費用の記帳日・科目・支払方法を変更せず、新規費用を作成しない。操作の再送は既存 operationId の冪等性を利用。
- 2026-10-24 ビックカメラ池袋西口店 6060円、名称差、候補複数、現金/立替/信用カード除外、日付範囲、再送、4件キューの独立処理、再起動バックアップを追加検証。共通 Firestore シナリオにも旧法人カード再利用・補録再送を追加。

本変更で Firestore Rules、正式帳票スキーマや歴史データ移行を変更しない。「メイン口座」31件を復元・削除しない。生産業務データへのアクセスは実行していない。ユーザー端末の4件キューの内容と処理結果は未確認であり、4件修復済みとは主張しない。ブラウザの既存ログインセッションは今回の利用可能なブラウザ一覧に存在しなかった。
