# Web/PWA login persistence

Root cause: `js/firebase-driver.js` selected `browserSessionPersistence`, which intentionally discards Firebase Auth state when the browser window closes. It now awaits `setPersistence(auth, browserLocalPersistence)` before subscribing to token changes. Existing open session logins migrate to local persistence. Sessions already cleared by the old release need one new login.

The application stays initializing until the first Firebase token observer callback. It then waits for verified custom claims before exposing admin/staff operations. The login form stays hidden during recovery. `dispose()` only removes listeners. Only the explicit logout button calls `signOut`. Password inputs are cleared after submission and application code never stores passwords.

Web and the relative manifest `start_url` use the same `firebase-config.json`, Firebase app name, project and auth domain. Reusing a Firebase app with different identity configuration is rejected. Firestore cache remains in memory; business caches remain scoped by project/company/UID. The service worker version changes so installed PWAs receive the corrected driver; cache cleanup touches CacheStorage only, not Firebase Auth storage.

Run `pnpm test` and `pnpm test:auth-persistence` after installing dependencies and Chromium (`pnpm exec playwright install chromium`). The persistence test downloads the exact Firebase CDN SDK used by the app, or accepts `FIREBASE_SDK_DIR` containing the three Firebase SDK files. It runs the actual driver, SDK, UI and service worker using disk-backed Chromium profiles. Auth HTTP responses and business listeners are fixtures; no production accounts or data are used. It verifies session-to-local migration, refresh, complete browser-process restart, manifest PWA entry close/reopen, explicit logout, and admin/staff restoration and access restrictions.

The manifest-entry test does not install a native mobile PWA. Device acceptance: on each supported installed PWA, log in as admin/staff, close the app completely, reopen and verify the account and role; explicitly log out, close/reopen and verify login is required. Use the same origin and browser/profile. Private browsing or browser policies that erase site data on exit cannot retain a login. The implementation does not fall back to transient persistence when local storage is unavailable.
